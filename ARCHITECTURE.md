# AI Email Agent - Архитектура и Технический Обзор

## Общий Обзор

AI Email Agent - это полнофункциональная система автоматизации управления электронной почтой, использующая искусственный интеллект для классификации и обработки писем.

## Компоненты Системы

### 1. Email Client (`src/email_client/client.py`)

**Функции:**
- Подключение к IMAP серверу
- Получение новых писем
- Парсинг email сообщений
- Операции: перемещение, удаление, архивирование
- Управление папками

**Технологии:**
- `imaplib` - IMAP протокол
- `email` - парсинг email
- SSL/TLS шифрование

**Ключевые методы:**
```python
connect()              # Подключение к серверу
fetch_emails()         # Получение писем
move_email()           # Перемещение письма
delete_email()         # Удаление письма
create_folder()        # Создание папки
```

### 2. LLM Classifier (`src/llm_classifier/classifier.py`)

**Функции:**
- Классификация писем через LLM
- Определение категории
- Оценка важности
- Детекция спама
- Рекомендации по действиям

**Поддерживаемые LLM:**
- OpenAI GPT (gpt-4-turbo, gpt-3.5-turbo)
- Anthropic Claude (claude-3)

**Категории классификации:**
- SPAM - спам и нежелательная почта
- PROMO - промо и реклама
- SOCIAL - социальные сети
- UPDATES - обновления и уведомления
- WORK - рабочая переписка
- PERSONAL - личная переписка
- FINANCE - финансы и платежи
- SHOPPING - покупки и заказы
- TRAVEL - путешествия
- IMPORTANT - важные письма

**Выходные данные:**
```python
{
    "category": "SPAM",
    "confidence": 0.95,
    "reasoning": "Объяснение",
    "suggested_folder": "Junk",
    "is_spam": True,
    "should_delete": True,
    "should_archive": False,
    "priority": "low"
}
```

### 3. Rules Engine (`src/rules_engine/`)

**Компоненты:**
- `database.py` - SQLite база данных
- `engine.py` - движок правил

**Функции:**
- Хранение пользовательских правил
- Применение правил к письмам
- Создание правил из естественного языка
- История обработки
- Статистика

**Типы правил:**
- FILTER - фильтрация
- DELETE - удаление
- MOVE - перемещение
- ARCHIVE - архивирование

**Операторы:**
- equals - равно
- contains - содержит
- starts_with - начинается с
- ends_with - заканчивается на
- regex - регулярное выражение
- not_equals - не равно
- not_contains - не содержит

**База данных (SQLite):**
```sql
-- Таблицы:
rules               # Правила пользователя
processed_emails    # История обработанных писем
action_logs         # Логи действий
statistics          # Статистика по дням
```

### 4. Telegram Bot (`src/telegram_bot/bot.py`)

**Функции:**
- Уведомления о новых письмах
- Статистика обработки
- Управление правилами
- Ручная проверка почты
- Просмотр истории

**Команды:**
- `/start` - начало работы
- `/status` - статус агента
- `/stats` - статистика
- `/rules` - список правил
- `/check` - проверить почту
- `/last` - последние письма
- `/help` - справка

**Поддержка естественного языка:**
```
"всё от amazon.com удалять"
"письма с темой 'реклама' перемещать в Promo"
"покажи статистику"
```

### 5. Configuration (`config/settings.py`)

**Функции:**
- Загрузка переменных окружения
- Валидация конфигурации
- Настройки для разных провайдеров
- Управление путями

**Конфигурируемые параметры:**
- Email провайдер и учетные данные
- LLM провайдер и API ключи
- Telegram настройки
- Интервалы проверки
- Параметры логирования

### 6. Main Agent (`src/agent.py`)

**Главный координатор системы**

**Жизненный цикл:**
```
1. Инициализация компонентов
2. Запуск Telegram бота
3. Главный цикл:
   - Подключение к почте
   - Получение новых писем
   - Для каждого письма:
     * Проверка на дубликат
     * Классификация через LLM
     * Применение правил
     * Выполнение действия
     * Сохранение в БД
     * Отправка уведомления
   - Обновление статистики
   - Ожидание до следующей проверки
4. Graceful shutdown при остановке
```

## Безопасность

### Защита данных:
- Пароли хранятся в .env (не в коде)
- .env файл в .gitignore
- Использование App Passwords для Gmail
- SSL/TLS для всех соединений

### Защита от ошибок:
- Try-catch блоки во всех критичных местах
- Логирование всех ошибок
- Graceful shutdown
- Защита от дубликатов
- Валидация конфигурации при старте

### Приватность:
- Локальное хранение данных
- Нет передачи данных третьим лицам (кроме LLM провайдера)
- Ограничение данных отправляемых в LLM (только subject + body preview)

## Производительность

### Типичная обработка:
- 1 письмо: ~2-5 секунд (включая LLM)
- 50 писем: ~2-5 минут
- База данных: instant queries
- Telegram: <1 секунда

### Ограничения:
- LLM API rate limits (зависит от провайдера)
- IMAP connection limits (зависит от провайдера)
- Telegram Bot API limits (30 сообщений/секунду)

### Оптимизация:
- Кэширование классификаций повторяющихся отправителей
- Batch обработка писем
- Асинхронные Telegram уведомления
- Индексы в базе данных
