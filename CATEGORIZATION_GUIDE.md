# Руководство по Автоматической Категоризации Писем

## 🎯 Как работает автокатегоризация

Агент автоматически классифицирует каждое письмо с помощью LLM и перемещает его из INBOX в соответствующую папку.

### Включение автокатегоризации

В файле `.env`:
```env
ENABLE_AUTO_CATEGORIZE=true
```

Это **включено по умолчанию** - все письма автоматически сортируются!

---

## 📁 Категории и Папки

Агент использует 10 категорий для классификации писем:

| Категория | Описание | Примеры отправителей |
|-----------|----------|---------------------|
| **SPAM** | Спам и мошенничество | Фишинг, мошенники |
| **PROMO** | Реклама и промо | Скидки, акции, рассылки |
| **SOCIAL** | Социальные сети | Discord, Telegram, LinkedIn, Facebook |
| **UPDATES** | Уведомления сервисов | GitHub, Jira, системные уведомления |
| **WORK** | Рабочая переписка | Коллеги, деловые письма |
| **PERSONAL** | Личные письма | Друзья, знакомые |
| **FINANCE** | Финансы | Банки, платежи, счета |
| **SHOPPING** | Покупки | Amazon, интернет-магазины |
| **TRAVEL** | Путешествия | Авиабилеты, отели |
| **IMPORTANT** | Важные письма | Срочные, критичные |

### Папки создаются автоматически

Агент автоматически создает папки при первом перемещении письма:
- `PROMO` - для рекламы
- `SOCIAL` - для соцсетей
- `WORK` - для рабочих писем
- И т.д.

## 🔧 Решение проблемы несовместимой классификации

### Проблема

> "Одинаковые письма попадают в разные категории с высокой вероятностью (0.8-0.9)"

### Что было исправлено

1. **Снижена температура LLM**
   - Было: 0.3
   - Стало: 0.1 (0.3 - 0.2)
   - Результат: Более детерминированные ответы

2. **Добавлен кэш классификации**
   - Одинаковые письма (по отправителю + теме) классифицируются один раз
   - Результат сохраняется в памяти
   - Последующие такие же письма используют кэшированный результат
   - Кэш хранит до 1000 записей

3. **Улучшен промпт**
   - Добавлено требование консистентности
   - Четкие определения каждой категории
   - Примеры использования
   - Предупреждение о завышенной уверенности

4. **Добавлена индикация кэша в логах**
   ```
   Автокатегоризация: SOCIAL (категория: SOCIAL, confidence: 0.85) (из кэша)
   ```

## 📊 Как работает классификация

### Шаг 1: Проверка кэша
```
Отправитель: noreply@github.com
Тема: [repo] Pull request #123
Хеш: md5(отправитель:тема)
```

Если хеш уже в кэше → используем сохраненную категорию

### Шаг 2: LLM анализ (если не в кэше)
- Анализируется тема, отправитель и начало письма (500 символов)
- LLM определяет категорию с уверенностью
- Результат сохраняется в кэш

### Шаг 3: Перемещение
- Письмо перемещается в папку категории
- Папка создается автоматически если не существует
- Действие логируется в базу данных

## ⚙️ Настройка точности

### Рекомендуемые настройки для консистентности

**Для Ollama (.env):**
```env
LLM_PROVIDER=ollama
OLLAMA_MODEL=llama3.2
OLLAMA_TEMPERATURE=0.1  # Низкая температура для консистентности
OLLAMA_MAX_TOKENS=800
```

**Для Perplexity (.env):**
```env
LLM_PROVIDER=perplexity
PERPLEXITY_MODEL=llama-3.1-sonar-small-128k-online
PERPLEXITY_TEMPERATURE=0.1  # Низкая температура
PERPLEXITY_MAX_TOKENS=800
```

**Для OpenAI (.env):**
```env
LLM_PROVIDER=openai
OPENAI_MODEL=gpt-4-turbo-preview
OPENAI_TEMPERATURE=0.0  # Максимальная детерминированность
OPENAI_MAX_TOKENS=800
```

### Объяснение temperature

- **0.0** - Максимально детерминированно (одинаковый результат всегда)
- **0.1-0.2** - Очень низкая вариативность (рекомендуется)
- **0.3-0.5** - Умеренная вариативность
- **0.7-1.0** - Высокая креативность (НЕ рекомендуется для классификации)

## 🎛️ Управление автокатегоризацией

### Включить/выключить

```env
# Включить автоматическую сортировку
ENABLE_AUTO_CATEGORIZE=true

# Выключить (письма останутся в INBOX)
ENABLE_AUTO_CATEGORIZE=false
```

### Комбинирование с другими функциями

```env
# Автоматическая сортировка + удаление спама
ENABLE_AUTO_CATEGORIZE=true
ENABLE_AUTO_DELETE=true  # SPAM будет удаляться

# Автоматическая сортировка + архивирование
ENABLE_AUTO_CATEGORIZE=true
ENABLE_AUTO_ARCHIVE=true  # Неважные письма в архив

# Только сортировка (рекомендуется)
ENABLE_AUTO_CATEGORIZE=true
ENABLE_AUTO_DELETE=false
ENABLE_AUTO_ARCHIVE=false
```

## 🔍 Диагностика проблем

### Письма попадают не в ту категорию

1. **Проверьте температуру**:
   ```bash
   grep TEMPERATURE .env
   ```
   Должна быть ≤ 0.2

2. **Очистите кэш** (перезапуск агента):
   ```bash
   ./start.sh
   ```

3. **Проверьте модель**:
   - `llama3.2` - хорошая точность
   - `llama3.1:70b` - отличная точность (но медленнее)

### Одинаковые письма в разные категории

**Это должно быть исправлено!** Если проблема сохраняется:

1. Проверьте что обновление применено:
   ```bash
   git log --oneline -1
   ```

2. Проверьте логи на наличие "(из кэша)":
   ```bash
   grep "из кэша" logs/email_agent.log
   ```

3. Если кэш не работает - сообщите в issue

## 💡 Советы по оптимизации

### Для максимальной точности

1. Используйте **OpenAI GPT-4** или **Claude 3**
   - Лучшая точность классификации
   - Стабильные результаты

2. Установите **temperature=0.0**
   - Максимальная детерминированность
   - Одинаковые письма → одинаковые результаты

3. Используйте **более мощную модель**
   - `llama3.1:70b` вместо `llama3.2`
   - Лучше понимает контекст

### Для скорости

1. Используйте **Ollama** с `llama3.2`
   - Быстрая классификация
   - Достаточная точность
   - Бесплатно

2. Включите **кэширование** (уже включено)
   - Повторные письма обрабатываются мгновенно

3. Уменьшите **MAX_EMAILS_PER_CHECK**
   ```env
   MAX_EMAILS_PER_CHECK=20
   ```

## ❓ FAQ

**Q: Можно ли изменить названия папок?**
A: Да, LLM предлагает `suggested_folder` на русском. Если не нравится, можно использовать правила для переопределения.

**Q: Как отключить перемещение для конкретной категории?**
A: Создайте правило с действием "skip" для этой категории.

**Q: Почему confidence всегда 0.8-0.9?**
A: Это нормально! LLM не дает 100% уверенность, так как интерпретирует текст. Важна не цифра, а консистентность.

**Q: Можно ли использовать свои категории?**
A: Пока нет, но можно создавать правила для дополнительной сортировки.

**Q: Кэш сохраняется между перезапусками?**
A: Нет, кэш в памяти. После перезапуска классификация начинается заново.
